# PR 1：多主题上下文与可校验树结果

基线：b5d8038f2a410ceaf14c21afe2cd57b33d04f770。独立分支
`feat/v2-verified-tree-context`，目标 `deploy/qwen-demo`。本轮不部署，不实施前端简化或 SSE。

## 主要讨论对象

`discourse_focus` 区分独立主问题、从属比较句和明确的“重点讨论”指示。
“AVL是什么？它与普通BST有什么区别？”的主问题是 AVL；反向定义普通 BST 时不会因后文
提到 AVL 而替换主语。对称比较或两个同等独立主题仍要求澄清，没有“默认第一个”规则。
Prompt 要求沿用 resolved_question 的主语并核查追问前提，普通 BST 不被说成必须旋转的 AVL。
它是有限的受控话语规则，不是通用自然语言指代消解。最多三轮及已有权限/代次边界不变。

## 算法与发布边界

`verified_trees.py` 是有界参考算法，不执行用户代码，也不是额外 Worker 或数据库索引。
BST/AVL 插入逐前缀检查全局中序严格有序、键集合和 AVL 每个结点的平衡因子。
LL/RR/LR/RL 有显式前置条件；旋转前后键集合相同，内部子树不能丢失。
已知错误“根2、左1、1的右孩子3”违反全局 BST 范围，会被检测，不能只比较直接父子。

B 树支持明确最大孩子数及插入后分裂的中位选择；B+ 树支持明确叶容量、左右叶分配、
复制右叶最小键和所需内部结点分裂约定。检查有序性、容量、最低占用、孩子数量、分隔范围、
记录键集合和叶子同层。已有左2右1及另一种明确左1右2规则有各自的参考结构，不互换。

具体结构只由服务端算法计算和渲染。Qwen 仍通过原 Guard 选择并解释当前课程规则，
必须先通过原严格答案/引用检查；有算法结果也不能挽救伪造、缺失、不相关或与题设约定冲突的引用。
最终答案明确写明“服务端算法计算并校验”，不把这部分当成模型独立算对或人工质量评分。
概念文字仍由 Qwen 生成。未经计算的树图、节点数字关系和代码围栏会保守拦截并按现有策略
有限重试。该展示检查不是任意自然语言事实的形式化证明，语义忠实性仍需人工审核。

每次返回前继续检查全部检索证据、知识库权限、hash、解析/索引代次和会话。
失败不保存 assistant，不留下半对消息；幂等缓存仍复核当前权限和来源有效性。
原单轮 `/rag/ask` 保留，增强树题行为；没有请求字段、数据库迁移或向量改动。

## 明确支持范围

- 从空树开始，最多16个、每个最多9位的整数键；AVL/BST 插入与单一旋转示例。
- B/B+ 最大孩子数3–8、叶容量1–8，明确约定的插入后分裂；单根叶特例不补造无关规则。
- 保留用户输入。若题称 LR 但实际输入触发 LL，明确说明实际类型，不替换成另一组键。
- 明确自拟示例会标出初始状态、输入和规则；给出的任意树图不会被偷换成自拟示例。

暂不计算：任意非空初始树、删除、一般前/中序重建、非整数键、超限序列、多个不同树家族的
合并构造、B 树插入前分裂和未覆盖的分裂约定。未知输入保守澄清；不是声称这些题无解。

## 来源约定一致性修复（PR #25 后续）

原先按树名及关键词判断 `rule_supported`，不能证明具体分裂约定。
现将这部分迁到 `tree_rule_evidence.py`，在有限语法内提取有类型的约定，
与 `Calculation.conventions` 记录的实际计算条件逐字段比较。
计算条件仅为溯源元数据；BST/AVL 插入、四种旋转及 B/B+ 插入/分裂函数未改动。

识别范围为正面陈述的阿拉伯数字容量、左右叶键数（包括完整的 `左1右2` 原子表达）、
父键复制右叶最小键/左叶最大键、插入前或溢出后分裂，以及中位键选择。
按树族主语及后续分句限定作用域；B 树的约定不能自动套给 B+ 树。
每个维度保存全部识别值，不用后一句覆盖前一句的矛盾规定。
奇数溢出时上下中位为同一键；偶数溢出只有“中间键”不足以确定上下选择。

来源被区分为：

- `explicit`：本次计算依赖的具体维度均有明确一致的资料规定。
- `principle_only`：有可识别的一般原理或部分一致规定；缺少的具体参数来自题设。
- `conflict`：资料明确值与本题条件不一致，返回 `200 insufficient_evidence / tree_rule_conflict`。
- `unrecognized`：约定措辞、条件/否定、备选规则等超出有限语法，返回
  `200 insufficient_evidence / tree_rule_unverified`，不宣称它们一致。
- `insufficient`：没有足够可识别的规则，仍返回 `tree_rule_evidence_required`。

一般原理识别使用有限的正面命题模板；树名加“叶”“分裂”等关键词本身不再算依据。
本轮检索到任一明确冲突或无法核对的相关约定，都会先澄清，不让模型通过省略该引用绕开。
生成后再次逐个检查实际引用，混入只有标题或不支持规则的片段会按原有限重试策略失败为
`502 validation_failed / tree_rule_citation_required`，不发布或持久化半对问答。
资料 hash、代次、权限、Cloud Guard 及幂等缓存的原校验继续生效。

最终回答分别列出“课程资料支持的原理”“课程资料明确给出的约定”及
“来自用户题设的构造假设”；每项教材规定只挂实际支持它的引用。
用户键序列、服务器计算得到的树结构，均不会标成教材逐项给出的解答。
未发生分裂的根叶特例不宣称教材支持某个未使用的分裂策略。

已有测试中的一种完整单次 B+ 分裂示例保留有限支持：必须匹配固定示例格式、
相同输入键序列、容量与分裂条件，且资料所列最终树与已校验结果一致。
回答标为“资料在相同输入示例中给出的约定”；输入不同或图无法核对时不会推广为通用规则。

这不是通用语义蕴含或教材事实审核。未覆盖的同义写法、中文数字约定、复杂条件、
跨片段省略与不同例子的规则绑定可能需要澄清，不能将未识别当成教材没有规定。
算法结果正确也不等于引用忠实性或概念解释已通过人工质量评分。
