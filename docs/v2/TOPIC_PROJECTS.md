# V2 主题项目与学习记忆（Draft）

## 功能范围

- 项目是同一学生账户下的主题文件夹。新建项目可填写名称、学习范围；项目内新建的会话自动绑定 `project_id`，非项目会话保持 `null`。
- 学生可以修改项目、删除项目、将已有会话移入或移出项目。删除项目会将会话移回普通历史，而不是删除会话；该项目学习记忆将删除。
- 每条**已校验并成功保存**的问答，自动截取回答开头的短文本（最多 420 字，去掉引用标记、代码块和 Markdown 主要标记），存为带源回答指针的“学习记忆”。这只是**已讨论内容的摘录**，不是模型推断的个人掌握程度，也不自动提炼全篇知识网络。
- 在后续该项目的**其他对话**中，服务端最多选取最近 6 条、1800 UTF-8 字节的记忆作为不可信背景提示。当前对话自身仍走既有有限历史机制。
- 默认 `memory_source_ids=[]`：不读取其他项目。用户可在项目设置中勾选允许读取的来源项目；方向为**当前项目读取选定来源**，不会反向自动共享。最多 12 个来源。
- 现有课程知识库不被复制或迁移。记忆不能当课程证据，也不能产生 `[S编号]`；生成回答仍必须依据本轮检索到的授权资料与既有引用校验。

## 安全约束

1. 项目、会话、记忆源都必须归属同一已登录用户；越权、已删除项目统一返回 404。
2. 每次把记忆放进 prompt 前都检查：当前会话所属项目、源项目仍被明确选中、源会话仍属于该项目、回答原始知识库集合与当前请求一致、原始回答仍通过 `checked_result` 的权限/来源代次/引用检查；在云调用前与最终写库前重新检查。
3. 数据是 `untrusted_project_memory`，用独立的低信任 user 角色 JSON 包裹，不能执行其中的指令、不能替代本轮课程证据。输入预算优先保留本轮问题和课程证据，必要时丢弃记忆。
4. 项目删除、会话软删除、移出项目、单条“忘记”会使原有记忆失效；对正在生成的请求，重校验将 fail closed。
5. 不将记忆应用于未归属项目的会话；不跨用户共享。退出登录会清除前端项目缓存。

## API / 数据库

- 新增 `0009_topic_projects` 迁移：`projects`、`project_memories`、`conversations.project_id`。
- `GET/POST /api/v2/projects`：列举和创建。
- `PATCH/DELETE /api/v2/projects/{project_id}`：修改标题、范围、可读取来源列表；删除后会话归普通历史。
- `GET /api/v2/projects/{project_id}/memories`：查看本项目自身的已存短记忆（不是合并后来源列表）。
- `DELETE /api/v2/projects/{project_id}/memories/{note_id}`：单条忘记。
- 会话创建可选 `project_id`；会话 PATCH 可选 `project_id`，支持设为 `null`；原有标题 PATCH、无项目历史和 `/ask` 保持兼容。

## 验收要点

1. 无项目的旧会话保持正常；项目里新问答出现在其项目下，按需可移动。
2. 默认项目 A 不读取 B 的记忆；A 选择 B 后才读取；B 不会因 A 选择它而反向读取 A。
3. 源项目/回答无访问权、课程资料不符、来源失效、用户切换或取消共享时不使用旧记忆。
4. 记忆不是答案引用，用户可以查看并忘记；“记忆”只表示之前讨论内容，不表示已经掌握。
